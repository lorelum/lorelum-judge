# 基于已有评价生成修改建议

## Why

Issue #61 需要让用户取得针对既有代码评价的具体建议，而无需批准修改或重新评价。#60 已收敛为定性报告，不引入数值评分或总分。

## What Changes

- 新增独立公开建议生成入口，消费已有评价与其版本化代码，支持全部或指定问题。
- 建立版本化建议记录，保留原报告、问题、证据及代码位置的可校验关联；中文报告区分处理必要性、调查缺口及需补充评价的疑似遗漏。
- 复用模型传输、取消和解析能力，验证模型结果；来源失配、材料不足、非法输出和失败不得冒充完整成功。

## Scope and Non-goals

建议不修改原评价、代码或文件，不执行命令、补丁、检查、重评或交付；不调用 #52，不将建议视为修改授权。不引入评分、缓存、重试、多轮辩论或新的来源读取能力。真实模型仅在服务、凭据和费用均获授权时调用。

## Capabilities

### New Capabilities
- `judge-code-suggestions`: 基于已有代码评价的独立只读建议生成与报告。

### Modified Capabilities

无。

## Impact

Refs #61，依赖 #60。protocol 拥有建议记录和验证，judge 拥有生成与展示；runtime 和 provider 复用现有端口。先严格验证 OpenSpec 并以同一分支和 PR 先提交设计，再继续实现。
