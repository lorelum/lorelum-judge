# 设计：代码评价后的修改建议

## 背景与边界

#60 的 `CodeEvaluationReport/v1` 保留问题、证据与 `SourceSnapshot/v1`，不包含数值评分。建议是独立消费结果，不是 measurement、gate 或已获批准的修改计划。只使用调用方提供的报告和快照，不读取文件、运行命令、重评或调用 #52。

## 公开接口与所有权

在 judge 增加 `generateCodeSuggestions(input, ports)` 和确定性中文 renderer。input 接收原评价、可选问题 ID、可选用于一致性核对的代码快照；省略问题选择表示全部，重复、未知或显式空选择为输入错误。默认使用原评价保存的代码。允许消费有效 partial 评价中的合法问题，但必须保留其不完整限制；无可定位问题时明确返回缺口。

protocol 定义独立版本的建议结果与报告及其验证；judge 负责投影、单次模型调用、严格解析和展示。复用既有模型 port、取消及失败处理；不改变现有评价、measurement、evidence、calibration 或 gate 契约。保留原报告 identity、source identity、实际代码 identity、选择、模型方法和响应事实以便追溯。

## 版本与证据

校验原报告及其结果、所选问题与证据。显式快照按来源 item、路径、side、version、文本、范围及关联比较核对，而非只信任调用方提供的 contentIdentity；与原始快照不一致或无法核实的部分不能产生确定性修复。原快照不证明它仍是当前工作区或 PR；报告应明确针对固定版本。使用现有投影助手核对本次模型实际可见的完整行，不引用截断或不可见位置。能独立处理的其他问题可继续；不能处理的问题明确列为缺口。

## 建议与限制

建议引用选定问题和该问题已有证据，包含绑定来源位置、处理类型（必须处理、可选优化、偏好）、必要性与优先级理由、具体方向、影响、检查方法与未确定前提。仅实质不同方案列出适用条件和代价；短示例允许存在，但必须固定为未验证，检查也必须标明未执行。分类不是 gate 或授权。严重问题不因整体情况而省略；不能由低分触发统一重构。

证据不足可给调查或补资料建议。疑似遗漏单独标注需要补充评价并引用可见材料，不伪造原问题、结论或证据。每个选择的问题须由建议或明确缺口覆盖；不为填满分类或方案数量编造条目。

## 模型、验证和终态

普通有效请求最多一次建议模型调用，不调用评价入口。工具列表为空；报告及代码是非可信数据，不能授予读取、执行或披露权限。对原本来自读取器的内容仍须取得模型披露许可。严格检查模型输出结构、选择范围、证据归属、代码版本及可见行；不修补、重试或静默丢弃坏项后宣称完整。调用失败、非法输出、取消和迟到响应分别保留真实状态，取消为终态。结果区分 completed、partial、failed、cancelled；部分合法结果与缺口可共存，但不能冒充完整成功。自然语言语义正确性不能仅由结构校验证明。

## 验证及风险

使用确定性替身覆盖单项/全部、不同方案、缺证据、失效版本、非法引用、疑似遗漏、示例未验证、失败与取消，比较原报告不变。公开入口 smoke 使用 #60 真实生成的评价经模型传输生成建议并展示，不注入预制完整报告；运行 strict OpenSpec 验证及 `bun run validate`。真实模型仅在授权且配置可用后调用，人工核对建议；未执行时明确说明质量未验证。无新增外部依赖。
