# 本地工作区

开发中的 #68 草稿入口，依赖未合并的 #64 / #67；不表示正式发布。仅本机单用户访问；模型、项目和沙箱权限留在宿主。首批安全发现和执行需要支持 `openat2`、bubblewrap 与必要 namespace 的 Linux。请先阅读 `packages/runtime-bubblewrap/README.md` 中的工具链、mount、权限和共享内核边界。

## 准备与运行

使用 Bun 1.4.2 和 Node 22.21.0。在已获 `lorelum/lumen-ui` 私有仓库读取权限的环境：

```sh
bun run prepare:lumen
bun install --frozen-lockfile
bun run workspace:local
```

准备脚本将组件库固定在 `b95a5409bfaba0e0f8db65c7a82257425f2ca99e`，在忽略的 `.lumen-cache/` 中构建本地包；不提交组件源码或包产物。公开仓库的 CI 需要 `LUMEN_UI_READ_TOKEN` secret 读取该私有仓库；未配置时 CI 无法准备页面依赖。外部消费者也需要组件库读取权限。离线演示运行时不调用外部服务；首次准备依赖仍需要仓库访问与包安装。

公开 fork 的 pull request 默认拿不到上游仓库的 Actions secrets，因此上述 CI 步骤也不能读取私有组件库；不要使用 `pull_request_target` 或向不可信代码暴露 token 来绕过该限制。

宿主默认只监听随机 loopback 端口；可用 `LORELUM_WORKSPACE_PORT` 指定端口。可在页面配置 OpenAI-compatible 端点、模型名称及可选 API 密钥，也可在启动环境设置 `LORELUM_MODEL_ENDPOINT`、`LORELUM_MODEL_NAME` 和可选 `LORELUM_MODEL_API_KEY`。页面提交后清空密钥输入，密钥仅存于宿主内存，不写入状态、事件、日志或文件。不要把密钥发到对话或放入仓库。接收方地址或模型配置包含当前或历史密钥（包括 URL 编码）时，宿主会拒绝该配置；与状态协议字段冲突的密钥也会被拒绝，避免脱敏破坏状态结构。

页面提供三个验收入口：代码或 PR 评价调用 `evaluateCode`；修改建议消费当前评价并调用 `generateCodeSuggestions`；修改计划与执行复用工作流。评价输出定性结论与问题依据，不提供数字分数；建议不执行、不修改代码。仅实际读取项目或执行修改时需要项目路径。连接检查和每次模型请求在发送前展示接收方、配置和完整消息并要求明确同意。模型配置或连接失败时不会静默回退到离线模型。确定性离线演示不是通用模型。

评价支持代码片段和公开 GitHub PR URL；受所选仓库的读取范围限制，跨仓库 fork 的来源可能无法取得，私有仓库认证尚未接入页面。建议使用当前会话完成或部分完成的评价结果。Windows 上执行修改需在 WSL 启动宿主；在 WSL 中可直接输入 Windows 盘符路径，由 `wslpath` 转换后仍须通过现有文件系统和沙箱检查。盘符路径转换成功不保证所有挂载布局都支持执行。

离线模型确定性地把用户选择的单个文本文件替换为用户提供的内容；它不理解任意自然语言，也不代表真实模型质量。检查命令由用户填写并审核；独立运行和固定 program checker 以实际候选与检查证据判断。未校准的结果不能作为强制 gate。命令仅能读取整个私有副本；网络、home、原始 Git 元数据、命令根级写入、硬费用、内存和文件读写字节限制均不支持。

选择目录前先输入需要排除的相对文件路径，排除先于正文读取。凭据检测无法识别所有可逆编码，排除敏感文件并逐次检查完整披露仍是必要边界。页面展示发现的现场、计划、独立权限和实际事件；计划确认不授予执行权限。执行后可单独允许本地显示差异，不等于向模型披露。原始工作树不会自动写回；不执行 commit、push、merge、release 或 deploy。刷新只显示当前内存状态，不补发断线事件；服务重启丢失会话和授权。
