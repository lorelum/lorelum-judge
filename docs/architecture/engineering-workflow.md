# Engineering workflow 阶段连接

本设计索引对应 #11；各阶段的 issue 和 OpenSpec 是该阶段的详细权威。当前不能因索引存在而声称能力已实现。

```text
A #52 计划和明确确认
  → B #53 独立授权、隔离修改、独立取证和检查点
  → C #54 公开评审与单次报告
  → D #55 核对现场后恢复及累计预算
       ├─ E #56 已核实问题的修复和证据更新
       ├─ F #57 单独获批的交付
       └─ G #58 指定时机的经验整理
  → H #59 真实故障及跨阶段组合验证
```

A–C 只构成单次闭环；D–H 未因 A 完成而实现。A 拥有来源追溯、计划版本和确认；B 拥有真实隔离、权限、检查点及用量事实；C 拥有评审结果与报告组合；D 拥有恢复与累计预算；E 拥有基于证据的修复循环；F 拥有逐项授权交付；G 拥有经验输出；H 验证真实故障组合。

共同约束：计划确认与操作权限分开；任何权限越界、撤销或失效必须停止。隔离无法落实时拒绝执行。保留用户原有修改的来源；不把实现者自述当独立证据。workflow 消费 judge 公开结果，不重新定义 measurement、质量或 gate；缺证不伪造通过或失败。quality accept 不授予 commit、push、merge、release 或 deploy 权限。
